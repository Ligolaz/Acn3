# Практична робота №9

## Тезисно що було зроблено

- Дослідження облікових записів користувачів у системі через **getent**
- Отримання адміністративного доступу до захищених файлів **shadow**
- Аналіз впливу прав власності на можливість редагування та видалення файлів
- Перевірка прав доступу до системних директорій та бінарних файлів
- Порівняння поведінки прав доступу на різних файлових системах: **ext4** та **tmpfs**

## Програмні вимоги

- Середовище запуску - термінал Linux (Ubuntu)
- Компілятор - GCC
- Права користувача - sudo

## Збірка та запуск

### 1. Перегляд облікових записів (Завдання 1)

Програма читає базу даних користувачів і знаходить записи з UID вище заданого порогу.
Це дозволяє ідентифікувати звичайних та системних користувачів, окрім поточного:
```
user@user:~/lab9$ ./1 1000
Found: nobody (UID: 65534)
```

### 2. Доступ до файлу shadow (Завдання 2)

Демонстрація отримання доступу до найбільш захищеного файлу системи, де зберігаються хеші паролів.
Виконання вимагає введення пароля адміністратора всередині програми:
```
user@user:~/lab9$ ./2
[sudo] password for user: 
root:*:20305:0:99999:7:::
daemon:*:20305:0:99999:7:::
...
```

### 3. Копіювання та видалення (Завдання 3)

Досліджено ситуацію, коли файл належить root, але лежить у домашній папці користувача.
Було підтверджено, що право на видалення залежить від прав на директорію, а не на сам файл:
```
user@user:~/lab9$ ./3
Creating file as user...
Copying to home as root...
User trying to edit...
Edit denied
User trying to delete...
rm: remove write-protected regular file '/home/user/copy.txt'? y
Deleted successfully (dir perms allowed it)
```

### 4. Перевірка ідентифікаторів (Завдання 4)

Програма виконує системну ідентифікацію, виводячи ім'я поточного користувача та детальний список усіх груп, до яких він належить (включно з групою sudo):
```
user@user:~/lab9$ ./4
Running whoami:
user

Running id:
uid=1000(user) gid=1000(user) groups=1000(user),4(adm),24(cdrom),27(sudo)...
```

### 5. Тестування прав 640 (Завдання 5)

Було створено файл, власником якого став root, а групою - sudo.
Результат показав, що користувач може читати файл через групові права, але не має дозволу на запис у нього:
```
user@user:~/lab9$ ./5
Creating file...
Root taking ownership, perms 640...
Testing read for user:
Hello
Read OK
Testing write for user:
Write Failed
```

### 6. Сканування прав системних файлів (Завдання 6)

Програма проаналізувала доступність критичних файлів ОС.
Встановлено, що пересічний користувач може читати паролі (passwd), запускати утиліти (ls), але повністю заблокований у доступі до shadow:
```
user@user:~/lab9$ ./6
Checking: /etc/shadow
-R -W -X
Checking: /etc/passwd
+R -W -X
Checking: /usr/bin/ls
+R -W +X
```

### 7. Поведінка файлових систем (Завдання варіанту 4)

Було протестовано роботу прав доступу на дисковій системі ext4 та системі в оперативній пам'яті tmpfs.
В обох випадках механізм обмежень спрацював ідентично, заборонивши читання файлу з правами "тільки виконання":
```
user@user:~/lab9$ ./7
---Testing FS: ext4---
Denied
Read attempt: Deletion: Success (Dir perms allow this)

---Testing FS: tmpfs---
Denied
Read attempt: Deletion: Success (Dir perms allow this)
```

## Висновки

У роботі було розібрано систему безпеки та розмежування прав доступу в лінуксі.
З точки зору системного програмування, було продемонстровано роботу облікових записів із файлами через системні виклики та стандартні утиліти.

Було проаналізовано підсистему керування користувачами та правами доступу, яка є критичною для стабільності системи.
На практиці було показано, як у лінуксі працюють загальні правила безпеки стандарту POSIX.
Система чітко розрізняє, що дозволено робити власнику файлу, що його колегам по групі, а що всім іншим людям.
Розуміння цих правил є дуже корисним, адже саме завдяки їм звичайний користувач не може навіть випадково підгледіти паролі інших людей або
зіпсувати важливі налаштування системи (приклад з файлом /etc/shadow).

Окрему увагу було приділено тому, як видаляються файли.
З'ясувалося, що можливість видалити файл залежить не від його особистих налаштувань, а від прав на папку, в якій він лежить.
Це показує, що в Linux папка є головною над своїм вмістом: якщо є ключі від папки, можна викинути з неї будь-який файл,
навіть якщо заборонено його відкривати чи читати.
