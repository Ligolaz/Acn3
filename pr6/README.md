# Практична робота №6

## Тезисно що було зроблено

- Аналіз системних подій за допомогою утиліти perf
- Вимірювання кількості сторінкових переривань (**page-faults**) під час запису у спільну пам'ять
- Дослідження поведінки ядра Linux при клонуванні процесу через **fork()**

## Програмні вимоги

- Середовище запуску - термінал Linux (Ubuntu)
- Компілятор - GCC
- Утиліта - perf

## Збірка та запуск

### Сторінкові переривання при copy-on-write (Варіант 4)

Написано програму, яка виділяє буфер розміром 100 МБ. Спочатку батьківський процес заповнює цей буфер даними, далі викликається fork(), який створює дочірній процес

Завдяки механізму Copy-on-Write, операційна система не копіює фізичну пам'ять миттєво. Батько і дитина використовують одні й ті самі сторінки пам'яті в режимі read only.
Копіювання відбувається лише в момент, коли дочірній процес намагається записати нові дані в буфер. Процесор генерує **page fault**, 
ядро ОС перехоплює його, копіює конкретну сторінку пам'яті для дочірнього процесу і дозволяє запис

Для підрахунку цих подій використано утиліту perf. Результат у 51к переривань складається з двох частин - первинне заповнення пам'яті батьком та Копіювання сторінок для дитини при спробі запису (Copy-on-Write):

**Компіляція та запуск:**
```
user@user:~/lab6$ gcc 4.c -o 4
user@user:~/lab6$ sudo perf stat -e page-faults ./4
[sudo] password for user: 

 Performance counter stats for './4':

			51,290		page-faults                                                           

		0.133098370 seconds time elapsed

		0.002003000 seconds user
		0.131124000 seconds sys
```

## Висновки

Було розібрано механізм оптимізації роботи з пам'яттю, який реалізує Менеджер віртуальної пам'яті (частина ядра ОС).
Тобто було досліджено поведінку ядра при створенні нових процесів та доступі до спільних ресурсів.

Виконання проводилося на Linux, де системний виклик fork() працює через механізм Copy-on-Write.
Механізм робить наступне - замість миттєвого дублювання всієї пам'яті, процеси спільно використовують одні й ті самі фізичні сторінки, доки не відбудеться спроба запису, що є важливим для швидкодії системи Linux, де створення процесів відбувається дуже часто.

Для аналізу було використано утиліту perf. Було зафіксовано page faults (сторінкові переривання) - це момент, коли процесор сигналізує ядру про спробу запису в захищену спільну пам'ять.
Це ілюструє концепцію віртуальної пам'яті, де програма оперує віртуальними адресами, а операційна система прозоро керує фізичним розміщенням даних.
