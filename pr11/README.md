# Практична робота №11

## Тезисно що було зроблено

- Написання програми для автоматичного відстеження крашів
- Отримання детальної інформації про стан процесора у момент збою системи
- Реалізація безпечного виводу даних через системний виклик **write()**
- Виведення значень головних регістрів: **RIP, RAX, RSP, RBP**
- Забезпечення роботи коду на різних архітектурах через перевірки у коді

## Програмні вимоги

- Середовище запуску - термінал Linux (Ubuntu)
- Компілятор - GCC з вимкненою оптимізацією при компіляції -O0

## Збірка та запуск

### 1. Система логування при падінні (Завдання варіанту 4)

Було розроблено програму, яка працює як чорна скринька(helicopter's black box reference).
Якщо стається помилка, наприклад, звернення за нульовою адресою, спеціальний обробник витягує стан регістрів прямо з пам'яті процесора.
Для безпеки замість printf використано прямий запис у термінал, щоб програма не зависла під час падіння.

Компіляція та запуск:
```
user@user:~/lab11$ gcc -Wall -Wextra -O0 -g -no-pie 1.c -o 1
user@user:~/lab11$ ./1
App running. Triggering crash...

CRASH LOG START.
Signal received: SIGSEGV (Memory Corruption)
Fault address: 0x0000000000000000

REGISTER DUMP:
RIP: 0x00000000004014ba
RAX: 0x0000000000000000
RSP: 0x00007ffd155dd7c0
RBP: 0x00007ffd155dd870
CRASH LOG END.
```

## Висновки

У роботі було розібрано, як операційна система обробляє аварійні ситуації.
З точки зору системного програмування, було показано взаємодію між ядром та програмою - коли стається збій, ядро передає нам останні дані стану процесора, який ми можемо проаналізувати.

Роботу було зроблено на лінуксі, оскільки ця система дає прямий доступ до апаратної частини через структуру ucontext_t.
Це дуже корисно для створення надійного ПО, де важливо знати точну причину падіння без використання дебагерів.
Дотримано стандартів POSIXу щодо використання безпечних функцій, а саме write замість printf, щоб вивід працював коректно навіть у критичний момент.

Також було приділено увагу тому, щоб програма могла працювати на різних процесорах.
Через спеціальні перевірки в коді, програма видасть адресу помилки на будь-якій системі, а детальний список регістрів покаже там, де це технічно можливо.
