# Практична робота №10

## Тезисно що було зроблено

- Налаштування просунутих обробників сигналів через **sigaction**
- Вилучення діагностичної інформації при аварійному завершенні
- Реалізація безпечного циклу очікування для **nanosleep** при перериванні сигналами
- Організація передачі даних між процесами за допомогою **real-time signals**
- Дослідження спільного використання файлового вказівника offset після виклику **fork()**

## Програмні вимоги

- Середовище запуску - термінал Linux (Ubuntu)
- Компілятор - GCC

## Збірка та запуск

### 1. Діагностика крашу (Завдання 1)
Використано структуру siginfo_t для перехоплення помилки сегментації.
Програма вивела адресу 0x0, яка спричинила збій, та стан регістрів процесора, RIP, RSP, що дозволяє точно локалізувати проблему в системному коді:
```
user@user:~/lab10$ ./1
About to crash. PID=3664
=== crash captured ===
signal: 11
si_code: 1
fault address: 0x0
RIP: 0x4016b6
RSP: 0x7fffe079e470
```

### 2. Безпечне переривання сну (Завдання 2)
Продемонстровано роботу з сигналом SIGUSR1, який перериває системний виклик очікування.
Завдяки реалізованому циклу, програма розрахувала залишок часу і доспала необхідний термін, не виходячи з режиму сну завчасно:
```
user@user:~/lab10$ ./2
PID=3696. Run 'kill -USR1 3696' to interrupt
Sleeping 5s with restart loop...
Finished. Interrupted by USR1: 1
tick 1
tick 2
tick 3
tick 4
tick 5
```

### 3. Передача даних через сигнали (Завдання 3)
Реалізовано модель підписник-видавець на базі real-time сигналів.
Програма підтримує чергу сигналів та дозволяє передавати цілі числа від одного процесу до іншого через функцію sigqueue:
```
# Термінал 1 (Subscriber)
user@user:~/lab10$ ./3 sub
Received value: 228 from PID: 3711
Received value: 1337 from PID: 3712
Received value: -1 from PID: 3713
```

### 4. Спільний дескриптор файлу (Завдання варіанту 4)
Досліджено поведінку файлових дескрипторів при копіюванні процесу.
Результат підтвердив, що батько і нащадок ділять один і той самий системний вказівник у файлі: вони пишуть дані послідовно, не перезаписуючи повідомлення один одного:
```
user@user:~/lab10$ ./4
File content:
Child data
Parent data
```

## Висновки

У роботі було розібрано підсистему сигналів ОС Linux - один із найважливіших механізмів взаємодії між ядром та програмою.
З точки зору системного програмування, було продемонстровано, як можна контролювати життєвий цикл процесу навіть у критичних ситуаціях, наприклад, при помилках доступу до пам'яті.

Роботу було зроблено на лінуксі, оскільки ця система дозволяє отримати доступ до низькорівневих контекстів процесора та підтримує real-time signals, які,
на відміну від звичайних, не губляться і можуть нести додаткову інформацію. Це ілюструє дотримання стандарту POSIX, який визначає, як саме програми мають спілкуватися з ядром через системні виклики.

Окрему увагу було приділено роботі з ресурсами. На прикладі fork() було з'ясовано, що копіювання дескрипторів - це не просто дублювання числа, а спільний доступ до одного об'єкта в пам'яті ядра.
Це показує, як ОС віртуалізує доступ до диску, дозволяючи декільком процесам працювати з одним ресурсом злагоджено.
Використання сигналів дозволяє системі працювати швидше, використовуючи менше оперативної пам'яті та буферів.
