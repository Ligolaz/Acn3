# Практична робота №7

## Тезисно що було зроблено

- Використання **popen()** для передачі даних між процесами через канали
- Імітація роботи системних утиліт: **ls**, **grep** та **more**
- Реалізація рекурсивного обходу дерева директорій
- Керування правами доступу до файлів та їх видаленням
- Вимірювання часу виконання коду та робота з рандомом
- Моделювання черги задач з управлінням станами без потоків

## Програмні вимоги

- Середовище запуску - термінал Linux (Ubuntu)
- Компілятор - GCC
- Утиліти - ps, more, grep

## Збірка та запуск

### 1. Робота з popen (Завдання 1)
Передача виводу команди ps aux в утиліту more через програмний канал. Це дозволяє переглядати великий об'єм системних даних посторінково:
```
./1
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.2  22948 14368 ?        Ss   12:10   0:01 /sbin/init
...
```

### 2. Імітація ls -l (Завдання 2)
Отримання виводу прав доступу, власника та розміру файлів за допомогою структур stat у поточному каталозі:
```
./2
-rwx 1 user user 16136 1
-rw- 1 user user 392 1.c
drwx 3 user user 4096 folder
```

### 3. Пошук слова у файлі (Завдання 3)
Знаходження заданого слова в текстовому файлі через функцію strstr. Програма виводить лише ті рядки, що містять шуканий підрядок:
```
./3 horse yuh.txt
I'm on a horse. You're on a white horse, and I'm on a white horse.
```

### 4. Посторінковий перегляд (Завдання 4)
Читання файлів із зупинкою кожні декілька рядків для імітації утиліти more. Реалізовано очікування вводу від користувача для продовження перегляду тексту:
```
./4 huh.txt wuh.txt
--- File: huh.txt ---
First to the parade, and then we'll go to the officers' club.
...
[Press Enter]
```

### 5. Рекурсивний список файлів (Завдання 5)
Обхід файлової системи для виведення всіх вкладених об'єктів. Програма аналізує тип елемента та рекурсивно заходить у підкаталоги:
```
./5
./folder/subfolder/f2.txt
./folder/f1.txt
./1.c
```

### 6. Сортований список папок (Завдання 6)
Збір списку підкаталогів поточної папки з подальшим алфавітним сортуванням. Для впорядкування назв використано функцію qsort:
```
./6
folder
```

### 7. Зміна прав доступу (Завдання 7)
Інтерактивна зміна прав доступу за допомогою системного виклику chmod. Програма знаходить вихідні коди та пропонує надати право на читання іншим користувачам:
```
./7
Found 11.c. Add read for others? (y/n): y
```

### 8. Вибіркове видалення (Завдання 8)
Програма перелічує файли та запитує підтвердження на їх видалення. Використано функцію remove для очищення робочого каталогу:
```
./8
Delete delete_me.txt? (y/n): y
File "delete_me.txt" deleted
```

### 9. Вимірювання часу (Завдання 9)
Замір тривалості виконання сегмента коду в мілісекундах. Для отримання точного часу використано функцію clock:
```
./9
Work done in: 202.04 ms
```

### 10. Генерація випадкових чисел (Завдання 10)
Створення дробових чисел у заданих діапазонах через нормалізацію виводу rand(). Для унікальності послідовності використано ініціалізацію через час системи:
```
./10
Rand 0-1: 0.925086
Rand 0-100.0: 45.955122
```

### 11. Черга задач (Завдання варіанту 4)
Моделювання життєвого циклу завдань за допомогою переліку станів. Зміна статусів, Pending, Running, Done, відбувається програмно без використання потоків або сигналів:
```
./11
Queue Ready:
Job 1 is Pending
Starting Job 1...
Job 1 is Running
Pausing Job 2 and finishing Job 1...
Job 1 is Done
```

## Висновки

Було розібрано принципи взаємодії програми з файловою системою та процесами в лінуксі.
На практиці продемонстровано роботу з системними структурами даних для отримання метаданих файлів та каталогів.

Показано роботу програмних каналів для передачі інформації між окремими процесами.
Реалізація аналогів системних утиліт дозволила зрозуміти логіку їх функціонування на рівні системних викликів.

Окрему увагу було приділено моделюванню логіки процесів.
На прикладі черги задач було підтверджено, що складні стани виконання можна контролювати всередині програми без використання додаткових ресурсів ядра ОС.
